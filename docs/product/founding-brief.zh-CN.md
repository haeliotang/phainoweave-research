# PhainoWeave — 创始简报

**状态：**2026-11-04 采纳 · **负责人：**Haelio Tang · **语言：**中文（投影；英文原文为准 / canonical English: [founding-brief.md](founding-brief.md)）

## 1. 一句话

**PhainoWeave 是开放基础设施：从环境观测中重建物理世界中不可见的事实——并让每一个重建出的事实保持可证伪。**

音频、图像、视频、气象、航空器航迹、卫星过境、地形：每一种都携带产生它的物理世界的痕迹。PhainoWeave 把这些痕迹变成证据，把证据变成*候选世界状态*，再把候选世界状态变成*第三方可以重跑的检验*。

*从观测到可验证的世界状态。*

**命名。**PhainoWeave 是平台品牌，取自希腊语 φαίνω（使显现、使可见）与 weave（编织）：把不同模态的证据交织起来，而不是堆叠。**Ambient Inference** 是其中推断引擎（inference engine）的名字（Rust crate 家族与 Python SDK）。*Environmental Intelligence Workbench* 是面向研究者的产品层；*Open World Evidence Infrastructure* 是面向开发者与研究机构的层。领域扩展不改变品牌；引擎名不会变成品牌名。

## 2. 问题：作为一个空缺来陈述

一段录音可以没有 GPS、没有 EXIF、没有任何元数据——却仍然被世界所约束：航空器的多普勒曲线、声音的传播路径、地形回声、太阳几何、当时的气象、生态分布范围、附近基础设施、两次过境之间的时间间隔。单独看，这些线索都很弱、精度各异、有时互相矛盾。今天的工具把它们当作彼此独立的把戏：一个仓库做航空器多普勒，一个基准做鸟鸣，一个模型做跨视角图像地理定位，一套 OSINT 工具做人工核验。

缺的不是又一个模态模型，而是**系统层**：异质、带噪、相关、部分受限许可的线索，如何变成一个**可验证、可反驳、可解释、可复现**的世界状态推断？

## 3. 输出的单元

PhainoWeave 不输出一个位置。它输出一个**附带验证器的世界状态假设（world-state hypothesis）**：

- 候选区域 / 候选时间窗 / 候选环境状态——以*分布*形式给出，而不是一个伪装成答案的点估计；
- 支持与冲突的证据，各自带溯源与已声明的误差；
- 物理约束残差（residuals）：该假设在多大程度上无法解释观测；
- 校准陈述（calibration），以及在证据不足时的明确**弃答（abstention）**。

形式上，目标是位置、时间与环境状态的后验：

```
P(L, T, S | O, D)
```

其中 `L` 为位置，`T` 为时间，`S` 为环境/事件状态，`O` 为观测证据，`D` 为公开数据与物理约束。交付物是这个区域/时间分布及其残差——不是 argmax。

## 4. 核心能力（唯一必须奏效的东西）

> **给定一个候选世界状态，系统独立预测在那里、那时应当被观测到什么，把预测与实际观测比较，并定位不一致之处。**

这是"AI 猜测世界"与"模型提出世界假设、物理约束检验它们"之间的分界线。项目中的其他一切，都是为了让这个回路可信：本体记录什么被观测、什么被推断、什么被核实；推断器契约强迫每个插件暴露残差；运行时让整个回路可重放。

## 5. PhainoWeave 不是什么

非目标是约束，不是愿景：

1. **不是 GeoGuessr。**地图精度只是副产品。没有证据、残差与校准的点估计是缺陷，不是特性。
2. **不是隐蔽的个人追踪工具。**默认输出是区域级。对私人的精确定位不在范围内；对*地点*的精确定位需要一个已授权、可审计的研究任务（见 [`docs/policy/ethics-and-privacy.md`](../policy/ethics-and-privacy.md)）。
3. **不是神谕。**语言模型可以提出特征、假设与评审意见；它们不得把未经核实的推断提升为事实，任何 LLM 输出都不是核验的最后一步。
4. **不是 Palantir 的克隆。**设计借鉴四项纪律——作战级世界本体（Foundry）、调查工作面（Gotham）、带评测的智能体工具链（AIP）、组件的持续部署（Apollo）。它直接拒绝军事目标定位、实时作战指挥与个人级行为监控。
5. **不是数据湖优先。**M0 用 SQLite 存核心对象；DuckDB/Parquet/H3 在分析负载需要时再引入。不拥有数据契约的平台不是平台。
6. **不是基础模型训练项目。**我们租用或包装专用模型；我们构建的是证据、约束与验证的基底。

## 6. 设计不变量

这些在对象模型（见 [`world-ontology.md`](../specs/world-ontology.md)）中强制执行，而非交给评审者的自觉。

| # | 不变量 | 后果 |
|---|---|---|
| I1 | **观测、推断、已核实事实是三个独立层** | "模型检测到飞机噪声" ≠ "当时有一架飞机" ≠ "这就是录音地点"。数据模型无法把第二层表达成第三层。 |
| I2 | **默认溯源（provenance）** | 每条派生记录都引用来源、许可、数据版本、处理程序、模型权重、参数与运行。使用 PROV-O 对齐的词汇，以保持互操作。 |
| I3 | **双时态（bitemporal）** | 事件时间（何时发生）与记录时间（我们何时得知）分离；历史重分析不得静默改写过去。 |
| I4 | **不确定性是一等公民** | 空间区域、时间区间与校准是类型化字段，不是报告时才加上的浮点数。 |
| I5 | **矛盾是数据** | 互斥的假设共存，并带显式冲突边。没有最后写入者获胜。 |
| I6 | **可复现性** | 运行记录固定观测哈希、数据快照、推断器版本、模型权重、物理参数、本体版本与执行环境。相同输入 ⇒ 相同记录，否则差异可归因。 |
| I7 | **追踪证据独立性** | 图像里看到的雨与音频里听到的雨是同一个气象事件，不是两票。相关证据不得相乘置信度。 |
| I8 | **弃答是有效答案** | 证据不足是成功模式，在评测中被度量，而不是需要掩盖的失败。 |
| I9 | **动作是类型化且受权限约束的** | 只有科学动作——`ExtractFeatures`、`ProposeHypothesis`、`RunSimulation`、`ChallengeHypothesis`、`RequestReview`、`PublishEvidence`——每个都有权限检查与审计记录。 |
| I10 | **许可与敏感度随数据传播** | `Source` 携带许可、访问条款、预期用途与敏感度。下游结果继承最严格的可适用约束。 |

## 7. 一表看领域模型

九个核心对象。规范定义、关系与动作在 spec 中；这里是共享词汇。

| 对象 | 含义 |
|---|---|
| `Source` | 原始数据来源，带许可、版本、获取方式、敏感度 |
| `Observation` | 录音、图像、视频或传感器记录——原始、不可变、内容寻址 |
| `Feature` | 从观测中提取的可测量（频谱、阴影方向、声学事件） |
| `Entity` | 现实世界中的对象或类别：航空器、铁路、天气系统、地形、物种 |
| `Event` | 在时间区间内发生的物理事件（过境、降雨、日食） |
| `Constraint` | 把观测与世界状态联系起来的物理或数据约束 |
| `Hypothesis` | 待检验的候选世界状态（位置 × 时间 × 状态） |
| `InferenceRun` | 一次执行：推断器、参数、数据快照、环境 |
| `Verification` | 对假设的检验：残差、支持、冲突、裁决 |

## 8. 架构

```
  观测 Observations（音频 · 图像 · 视频 · 传感器）
        │
        ▼
  数据织物 Data Fabric        适配器、归一化、版本、质量、许可
        │
        ▼
  世界本体 World Ontology     九个核心对象、类型化动作、权限  [Rust 核心]
        │
        ▼
  证据图 Evidence Graph       溯源、依赖、独立性、矛盾
        │
        ▼
  推断器 Inferencers          声学 · 视觉 · 天文 · 气象 · 生态
        │                    统一插件契约：假设、分数、残差、引用、错误、版本
        ▼
  验证器 Verifiers            多普勒运动学 · 太阳星历 · 声传播 ·
        │                    地形/几何 · 气象一致性
        ▼
  推理运行时 Inference Runtime  运行、调度、重放、反事实重跑
        │
        ▼
  界面 Surfaces               先 CLI · 后调查工作台（Tauri + React + MapLibre）
```

部署模式是分阶段的，不是同时的：**Local**（单研究者、隐私）、**Research Node**（实验室共享算力与索引）、**Cloud Worker**（批量公开数据）、**Edge Node**（野外传感器）、**Air-gapped**（归档、受限分析）。

## 9. 技术栈边界

- **Rust** ——核心运行时：本体契约、证据存储、调度、权限检查、事件日志、插件宿主、可复现运行。
- **Python** ——科学推断：DSP、计算机视觉、贝叶斯推断、物理求解器、统计校准、ML 实验。
- **DuckDB + Parquet/GeoParquet + H3** ——批量时空查询的分析层（M0 之后；核心对象先由 SQLite 承担）。
- **Tauri + React + MapLibre** ——调查工作台（M2），不是第一天。
- **接口** ——稳定的对象 API 与推断器 SDK，使声学研究者与生态学者无需读懂彼此的代码就能扩展系统。

## 10. 里程碑与验收

完整验收标准与顺序见 [`ROADMAP.md`](../roadmap/ROADMAP.md)。摘要：

| ID | 里程碑 | 承重验收 |
|---|---|---|
| M0 | **世界本体基座** | 一条已授权观测能产出完整的证据链；每条派生记录都可追溯到原始数据、版本与运行；双时态、矛盾与独立性不变量由测试强制。 |
| M1 | **声学推断纵切** | 在受控与公开许可的音频上，多普勒/运动学约束可证明地优于仅用学习先验；基准报告发布*包括失败*，含误差分布、候选覆盖率、假阳性、弃答。 |
| M2 | **调查与假设引擎** | 一次完整调查可重放；改动一个假设恰好标记受影响的推断；地图 + 时间线 + 证据图 + 模拟视图是同一个工作区。 |
| M3 | **跨模态推理与评测** | 在留出数据上多模态以所述幅度优于最好的单模态；相关证据导致的过度自信被度量并缓解；智能体/工具评测套件能比较版本。 |
| M4 | **分布式研究基础设施** | 同一任务在本地与独立节点上重放结果一致；跨版本的结果差异可定位到数据 / 模型 / 软件变化。 |

## 11. 评估立场

成功不是"猜对了多少位置"。被度量的集合是：

- 定位**误差分布**（不只均值）与候选区域**覆盖率**（给定面积下的召回）；
- **校准**（区域概率上的可靠性图、期望校准误差）；
- 系统所声称精度下的**假阳性率**；
- **弃答行为**——选择性风险/覆盖曲线，而非孤立的弃答率；
- **相关证据导致的过度自信**——来自同一物理事件的成对证据不得虚假地改善校准；
- **泛化**——在地理与时间隔离划分下，加上负例与空例；
- **重放确定性**——重跑的记录必须逐位相同，否则差异必须可归因。

预注册（preregistration）与阴性结果是必需的，不是可选项。见 [`benchmark-and-evals.md`](../roadmap/benchmark-and-evals.md)。

## 12. 硬边界（隐私、双重用途、法律）

1. **默认区域级。**精确空间输出需要显式、留痕的授权与明确的研究目的。
2. **不隐蔽追踪个人。**不输出以定位私人或暴露私人住所为目的的结果。个人级行为推断不在范围内。
3. **不做军事、目标定位、实时作战指挥或执法用途。**这些被排除在项目的预期用途、文档与示例之外。
4. **公开数据 ≠ 免费数据。**每个 `Source` 携带许可、访问限制与敏感度；结果继承它们。
5. **能力上线前先红队。**任何实质性提高精度的新模态，在合并前都要通过伦理评审与有记录的滥用测试。

细节、角色与评审程序：[`ethics-and-privacy.md`](../policy/ethics-and-privacy.md) 与 [ADR 0005](../decisions/0005-privacy-and-dual-use.md)。

## 13. 已知风险与开放问题

- **野外音频的泛化性未经证明。**公开的飞机多普勒复现在留出录音上报告：宽带样本 18 个中有 2 个、单音样本 14 个中有 1 个落在 3 km 半径内，中位误差约 12–13 km（外部主张，来自其公开评测；见[综述](../research/landscape.md)）。那是案例研究，不是能力估计。M1 必须度量它，包括失败。
- **数据天花板是真实的。**OpenSky 的完整历史存档受研究资格限制；ERA5 的分布式产品为 0.25°（约 25 km，原生网格约 31 km）、ERA5-Land 约 9–11 km、ECMWF IFS 约 9 km。它们都不支持街道级主张；校准必须说明这一点。
- **相关证据会膨胀置信度**——这是本项目最可能产出"看似合理的胡话"的方式。不变量 I7 正是为此存在；M3 度量它。
- **基准污染与领域漂移**——地理隔离与时间隔离划分是必需的，但没有哪种划分能完全证明泛化。
- **本体过度工程**——九对象模型可能变成官僚体系。M0 保持最小；新增需要 ADR。
- **外部数据漂移下的可复现性**——历史气象与航迹数据集会被修订。快照化数据版本是强制要求，不是建议。
- **法律暴露**——隐私法依司法辖区而异；对地点的精确定位可能使个人去匿名化。默认必须在没有逐次查询法律审查的情况下也是安全的。
