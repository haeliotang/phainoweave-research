# Cross-platform E0 reproducibility — measured report

**Status:** measurement complete, R1 not established · 2026-11-05 · **Owner:** founder · **Related:** [ADR 0012](../decisions/0012-research-grade-minimal-fabric.md) §6, [E0 report](2026-11-04-e0-synthetic-doppler.md), [PR-4 comparator](../../python/phaino_verify/), [protocol example](../../protocols/e0-cross-platform.example.json)

**What this report is.** The first real cross-platform comparison of the E0 artifact, run with the R0/R1/R2 comparator on two platforms. It measures differences per trial and per field, classifies them, and states what blocks R1 — it does **not** declare reproduction, and it does **not** freeze tolerances.

Reading: where the inverse problem is identifiable, cross-platform parameter differences are ~1e-9 — five to seven orders of magnitude below the E0 decision thresholds (1% `f0`, 2% `v`, 0.25 s `t0`, 5% `b`). ## 4. Difference classes found

| Class | Evidence | Interpretation |
|---|---|---|
| Scientific outputs, identifiable | params ≤2.3e-7 rel; `rel` fields ≤3.0e-4 rel but ≤4e-3 abs | Genuine but negligible cross-platform float difference |
| Scientific outputs, unidentifiable | `null_noise_only` params rel 0.32; standard errors up to rel 1.0 / abs 3.7e+23; condition number rel 0.29; correlations rel 0.45; worst-direction components rel 0.96 | A difference in a quantity the model itself says is unbounded. Comparing it as a pass/fail field is a category error |
| Implementation metadata | least-squares **iterations differ in 979/2500 trials**; `grad_norm` median rel diff 0.375; `n_starts`/rankings | Not scientific outputs; exact equality across platforms is not meaningful, though it confirms different arithmetic paths |
| Decisions | `converged` flips for exactly **1/2500** trials (`snr_+5dB`, trial 57); that propagates to `accepted` and to the condition's success count **100 → 99** (`accepted_rate` 1.0 → 0.99) | A genuine **decision instability**: parameters agree to ~1e-9 and every pre-declared tolerance passes, but a convergence flag near its threshold flips, changing a reported rate |

The instability case is the scientifically important one: the two runs agree on the numbers and disagree on a *decision*. That is the difference between "the fit succeeded" and "we know what happened", and it must be visible, not averaged away.

## 5. Why R1 is not established

Three blockers, each requiring a protocol feature that does not exist yet:

1. **Identifiability conditioning.** Null and degenerate trials must be compared on decisions and residuals only; parameter/SE/correlation fields need a reference-side identifiability gate (e.g. worst-direction relative SE below a threshold, or condition number below a bound), taken from the reference run and reported per trial. Without it, a whole-artifact R1 either fails forever or needs tolerances loose enough to hide real regressions.
2. **Decision-margin rule.** Convergence, acceptance and success are threshold decisions. A decision must be compared only when its deciding statistic is farther than a declared margin from the threshold; near-threshold decisions become `indeterminate`, are counted and reported, and a *material* change (a condition-level rate change) blocks the reproduction claim. This is not implemented in the comparator yet.
3. **Field classification completion.** Exactness belongs to ids, counts, version strings and decisions; numeric tolerance to scientific values; implementation metadata (iterations, gradient norms, start rankings) needs its own class so it is neither silently ignored nor treated as a failure.

Until those exist, the CI E0 job keeps doing what it does today: run the functional replay, retain the Linux artifact, and **not** claim R1.

## 6. Tolerances: measured bounds, deliberately not frozen

The measurement gives defensible *bounds* for a future protocol:

| Field class | Measured max (identifiable conditions) | Proposed bound | Rationale |
|---|---|---|---|
| fit parameters `f0`, `v`, `t0`, `b` | 2.3e-7 rel | rel 1e-5 (abs scaled: 5e-3 Hz, 2.5e-3 m/s, 2e-4 s, 3e-2 m) | ~40× measured worst; ~1000× below the 1–5% decision thresholds |
| fit residuals (`sse`, `rms_hz`, `sigma_f_hz`) | ~1e-9 rel | rel 1e-5 | same amplification argument |
| `rel`/`rel_abs` fields | ≤4e-3 abs | **abs only** 1e-6 | these are ratios near zero; relative comparison is meaningless |
| aggregate rates (`success.rate`, `accepted_rate`, `converged_rate`) | 1e-2 (decision flip) | abs 0 (exact) once decision margins exist | rates summarize decisions; tolerance hides instability |

These are **proposals**, not a frozen protocol. Per the ruling: measure first, derive from numerical error and decision thresholds, freeze before E2. They must be validated on a second platform pair (e.g. two Linux machines, different CPU/BLAS) before they are frozen, so the bound is not fitted to one pair.

## 7. What this does and does not show

- **Does show:** the implementation produces the same science up to ~1e-9 in identifiable conditions across two architectures; a real, reproducible-by-anyone claim about this artifact cannot be made on digests alone; and one decision in 2500 is not stated the same way on both platforms.
- **Does not show:** that E0's physics is right (generator and fit share a model); that real recordings behave this way; that a different implementation would agree (independent physical validation is a separate layer); that four-decimal rounding in the report would have hidden the instability.

## 8. Next unit (PR-4b) and exit criteria

| Item | Exit criterion |
|---|---|
| B1 identifiability-conditioned scope in the comparator | Null/degenerate trials compare decisions + diagnostics only; scope rule comes from reference-side SE; report says how many trials were scoped out |
| B2 decision-margin / indeterminate rule | Near-threshold decisions reported as indeterminate; stable decisions exact; material rate change flagged |
| B3 field classes finalized | Exact / numeric / diagnostic / implementation classes; no field unclassified |
| B4 protocol v1 from these bounds | Frozen after a second platform pair; protocol digest recorded; tolerances justified from measurement |
| B5 CI gate | Comparator runs on the uploaded Linux artifact against a retained reference; fails on `mismatch`; prints the R0/R1/R2 classification; `exact` never expected cross-platform |
| B6 independent physical validation | Separate implementation checks a fixed-truth physical prediction (scheduled after PR-4b, before E2) |

The result of PR-4b is not "make it green"; it is "make the comparison say precisely what is and is not reproduced, and fail when the science changes".

**Python patch versions are not identical yet** (3.14.9 vs 3.14.10): `setup-python` with `python-version: "3.14"` resolves the latest patch per runner, so the pin must name a patch (`3.14.9`) before the protocol is frozen. ### Pairwise results under protocol v2 (measured-draft, not frozen)

| Pair | R0 | R2 | R1-N | R1-D | reproduction_level | instability | rate changes |
|---|---|---|---|---|---|---|---|
| A ↔ B | pass | fail | **pass** | **fail** | R1-N only | 3 (trial 57) | 4 (100→99) |
| A ↔ C | pass | fail | **pass** | **pass** | **R1-N+R1-D** | 0 | 0 |
| B ↔ C | pass | fail | **pass** | **fail** | R1-N only | 3 (trial 57) | 4 (100→99) |

### The instability is architecture-linked, not OS-linked

The only decision that differs is the same near-threshold convergence on `snr_+5dB` trial 57 (`grad_norm` threshold 1e-6, margin 5e-7):

| Run | `grad_norm` | `converged` | accepted/success |
|---|---|---|---|
| A (macOS arm64) | 2.97e-12 | true | true |
| C (Linux arm64) | ~1e-12 class | true | true |
| B (Linux x86_64) | 1.056e-6 | false | false |

Both arm64 environments converge; the x86_64 environment stops just above the threshold. A↔C (same architecture, different OS and BLAS) reproduces decisions exactly; A↔B and B↔C (different architecture) do not. This is a robust, explainable finding: **the E0 convergence rule has a numerical boundary that one architecture path sits on**, so the E0 report's "100/100 at SNR ≥ −5 dB" is better stated as "99–100/100 depending on architecture".

### What this validates and what it does not

- **Validates the protocol's numeric scope:** tolerances were derived from A↔B, and R1-N passed unchanged on the two unseen pairs (A↔C, B↔C). The numeric rule did not need retuning for new environments — the held-out-pair validation the contract requires.
- **Does not validate R1-D:** decision equivalence fails on every pair involving x86_64. Reproduction claims stay at `R1-N only`; `R1-D` and the CI gate remain off until the decision rule is hardened.
- **Does not freeze anything:** protocol v2 is `measured_draft_not_frozen`; its digest is `0361b429…` (before strict materiality; the strict-materiality version is the one committed with PR-4b). Freezing still requires identical Python patch pins and a decision-stability fix.

### Required next steps before freeze (PR-4c)

1. Pin an identical Python patch on B and C and rerun; if patch availability blocks this, use a container image or `uv` to make the interpreter deterministic.
2. Harden the convergence decision: scale `grad_norm` by the residual/cost scale, or require a minimum iteration count / consecutive-iteration stability, so a path cannot stop within the margin band. This is a *model/estimator* change, not a comparator change, and it will change E0's digest — decide whether E0 is re-issued or E1 starts from the hardened rule.
3. Re-run the three-environment validation after (2); freeze the protocol only when R1-N and R1-D both hold on all three pairs.
4. Then enable the CI R1 gate (`--require both`) and record the frozen protocol digest in every report.
