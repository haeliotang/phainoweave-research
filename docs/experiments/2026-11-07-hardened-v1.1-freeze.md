# Hardened v1.1 candidate freeze and semantic comparison

**Status:** candidate-frozen; Linux CI semantic comparison passing, macOS arm64 cell pending · 2026-11-07 · **Decision:** [ADR 0027](../decisions/0027-hardened-v1.1-reproducibility-protocol.md) · **Protocol:** [`protocols/e0-hardened-v1.1.json`](../../protocols/e0-hardened-v1.1.json)

This record freezes hardened v1.1 as a **separate candidate reproducibility protocol**. It does not repair or supersede frozen E0.

## 1. Frozen ingredients

| Ingredient | Value |
|---|---|
| Estimator | `phaino_acoustics.fit_hardened`, `HARDENED_VERSION = 1.1.0` |
| Stall rule | indeterminate + `improvement_ratio < 0.25` → `rejected / model_inadequate`; the stall remains visible in `optimization_status` / `optimization_reason` |
| Input | E0 grid, 25 conditions × 100 trials, same seeds; base protocol `protocols/e0-cross-platform.v2.json` |
| Environment | Python 3.14.9, NumPy 2.4.4, SciPy 1.17.1, SymPy 1.14.0 |
| Targets | macOS arm64, Linux arm64, Linux x86_64; x86_64 retained |
| Comparator | `scripts/compare_hardened_v11.py`; primary fields come from the protocol and must match exactly; the canonical identity digest freezes all 2500 `(condition, trial, seed)` tuples; duplicate/short/wrong-identity artifacts fail before comparison; optimization diagnostics are reported, not hidden |

## 3. What this does not establish

- The local artifacts above were generated outside CI. CI now runs the same frozen protocol on Linux arm64 and Linux x86_64; run [42365583281](https://github.com/haeliotang/phainoweave/actions/runs/42365583281) passed the semantic comparison (0 primary mismatches). The macOS arm64 cell remains skipped because this private repository has no hosted arm64 runner.
- It is **not** E1 reproducibility; only 2500 synthetic E0-grid cases.
- It does **not** retroactively pass frozen E0; E0's x86_64 R1-D failure remains historical fact.
- It does **not** cover E1-C physical mismatch/false-accept behavior.
- R1-D remains non-blocking until the CI conditions in ADR 0027 are met; R2 remains reported-not-passed.

## 4. CI infrastructure note (2026-11-07)

The private repository does not have a GitHub-hosted arm64 macOS runner; the first CI attempt cancelled that cell before it started. The workflow now makes the macOS cell optional via the repository variable `MACOS_ARM64_RUNNER` (for example a self-hosted or larger runner label). Until that is configured, CI can verify Linux arm64 + Linux x86_64; the local macOS arm64 artifact is evidence but not an authoritative CI result. This is an infrastructure limitation, not a change to ADR 0027's target list.

## 5. Next gate

CI must run one frozen protocol at one code revision with the pinned environment on macOS arm64, Linux arm64 and Linux x86_64, compare semantically, and save the run IDs/artifacts. Only then can R1-D be proposed as blocking for hardened v1.1.
